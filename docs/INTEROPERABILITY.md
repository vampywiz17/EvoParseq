# Interoperability and source provenance

EvoParseq is a volunteer-run, independent open-source community project. The
project generates no revenue and has no company backing.
The product and protocol names in the documentation identify the services or
wire behavior with which EvoParseq aims to interoperate. The current client uses EvoParseq artwork.

## Transport implementations

- **Parsec compatibility.** The optional lowlat-based transport implements
  the wire behavior needed to connect to compatible Parsec hosts. EvoParseq vendors
  selected MIT-licensed components and preserves their copyright and license
  notices. The vendored directories record their upstream revisions and local
  changes. The settings label **lowlat** identifies the transport in the client.
  [lowlat transport adapter](../src-native/crates/lowlat/README.md)
- **Phaze compatibility.** The experimental transport is EvoParseq's
  independently written Rust implementation of behavior needed to interoperate
  with supported Phaze hosts. The shipped adapter uses EvoParseq source and
  open-source libraries. Names such as **Phaze** in the service selector identify
  the account and host service. [Phaze-compatible adapter](../src-native/crates/host-interop/README.md)
- **Public protocols.** The code also uses published standards such as WebRTC,
  ICE, STUN, TURN and DTLS. See the references for individual components and
  platform APIs. [Development references](NATIVE_REFERENCES.md)

## How compatibility was studied

The project used public documentation, published open-source implementations,
and observations of ordinary sessions on maintainer-controlled test systems.
For specific compatibility questions, the project also inspected installed
client or host binaries read-only and observed selected runtime behavior
on the test systems. The development references identify some of those
observations. Access to the test systems was authorized by their operator.
That authorization concerns the test environment and does not imply approval
or endorsement by the product vendors.

The purpose was to identify the information needed for the independent client
to exchange data with compatible hosts. The interoperable Rust code implements
the observed interfaces. Authentication and host approval remain part of the
connection. The project requires contributors to respect access controls and
use only IP, code and assets they are entitled to publish.

For future investigations, use public sources first and document the origin,
method and scope of any further observations. Limit inspection to information
needed for interoperability that is otherwise unavailable. The applicability
of a legal exception depends on the facts and jurisdiction, including how the
copy was obtained, what was inspected and what material is published.
[EU software directive, Articles 5–6](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32009L0024)
· [U.S. interoperability provision, 17 USC § 1201(f)](https://uscode.house.gov/us/usc/119-118/t17/s1201/)

## Test and release material

The Phaze adapter's offline tests use generated control messages, synthetic
credentials, and generated AAC or other bounded media fixtures. The lowlat
transport tests use synthetic local peers and credentials. Separate live tests
exercise compatibility with stock hosts. Live test results describe the tested
behavior and environment.

Checked-in video fixtures include synthetic media generated by the project and
selected fixtures from MIT-licensed lowlat, as documented beside the files.
Keep copyright and license notices with upstream data. Keep vendor executables,
disassembly output, raw session captures, credentials and user media out of
the repository and release packages. Document any new fixture's origin beside
the file. [Linux test media](../linux/tests/data/README.md)
· [Windows HEVC test media](../src-native/crates/video/fixtures/README.md)
